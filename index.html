01
Module 01 · Beginner

Start Here: Class Zero

This course assumes you have never written code and never heard of a database. Read the modules in order, like classes. After each one, open the Practice Lab in the top bar and type the examples yourself.

What is data?

Data is just recorded facts: a student's name, a product's price, today's temperature. Every app you use (banking, social media, shopping) stores and reads data all day.

What is a database?

A database is an organised, safe place to keep data so it can be found fast. Think of a school office. A loose pile of papers is hard to search. A filing system with labelled cabinets is not. The program that runs the filing system, storing, finding and protecting the papers, is called a DBMS (database management system). PostgreSQL is one.

What is a table?

Data inside a relational database lives in tables, like one sheet in a spreadsheet. Columns are the labels, and each row is one record, here one student.

idfull_nameemailgpa
1Ayesha Rahmanayesha@uni.edu3.80
2Tanvir Hasantanvir@uni.edu3.40

What is SQL?

SQL (Structured Query Language) is how you talk to the database. You describe what you want, and the database works out how. SELECT full_name FROM students reads almost like English: "show me the full names from students".

What is PostgreSQL?

PostgreSQL (say "post-gres-Q-L", or just "Postgres") is a free, open source DBMS. It runs as a server. Like a restaurant, you (the client) give an order (SQL) to the waiter, and the kitchen (the server) prepares and returns the result.

How to study

  • Green badges are beginner, yellow intermediate, pink advanced. Do not skip ahead.
  • Type every example yourself. Press Try on a code block to send it to the lab.
  • Errors are normal and useful. Break things on purpose.
Key takeaway

Database = organised tables. SQL = the language to ask for data. PostgreSQL = the program that stores the tables and understands SQL.

Module 03 · Beginner

Install PostgreSQL on Windows

The official installer is about 300 MB and includes the server, the psql command line and the pgAdmin app.

  1. Open postgresql.org/download/windows and choose Download the installer. Pick the newest version (16 or higher) for Windows x86 64.
  2. Run the downloaded .exe and allow administrator access.
  3. Keep the default folder and keep these components ticked: PostgreSQL Server, pgAdmin 4, Command Line Tools.
  4. Choose a password for the superuser postgres and write it down. It is hard to recover.
  5. Keep the default port 5432 and the default locale, then finish.
  6. Open the Start menu and run SQL Shell (psql). Press Enter four times to accept the defaults (server, database, port, user), then type your password. The password stays invisible while typing, which is normal.
  7. Test the installation:

Other ways

You can install from PowerShell with winget, or run PostgreSQL in Docker without installing it.

If something goes wrong

port 5432 already in useAnother PostgreSQL is running. Stop it or pick another port during install

Module 04 · Beginner

SQL Basics: Your First Statements

Before real queries, learn the grammar. A SQL statement is like a sentence: a keyword says what to do, and the rest says to what.

  • Every statement ends with a semicolon ;.
  • Keywords such as SELECT are not case sensitive. Convention: UPPERCASE keywords, lowercase names.
  • Text goes in single quotes like 'this'. Double quotes are for unusual names.
  • Comments: -- one line or /* many lines */.
  • Spaces and line breaks do not matter, so format for readability.
  • Name things in lowercase_with_underscores, with no spaces.

Anatomy of a statement

PartMeaning
SELECT full_namewhich columns to show
FROM studentswhich table to read
WHERE gpa > 3.5which rows to keep
;end of the statement

The five command groups

GroupCommandsPurpose
DDLCREATE, ALTER, DROPDefine structure
DMLINSERT, UPDATE, DELETEChange data
DQLSELECTRead data
DCLGRANT, REVOKEControl access
TCLBEGIN, COMMIT, ROLLBACKGroup changes safely

Reading error messages

  • syntax error at or near "x": a typo close to the word x.
  • relation "x" does not exist: wrong table name, or it is not created yet.
  • column "x" does not exist: misspelled column.
PracticeShow your own name and today's date in one statement.
Key takeaway

Errors are information, not failure. Read the first line and look at the word after near.

Tables and Data Types

A table stores rows; every column has a type that PostgreSQL enforces. Picking the right type is the cheapest form of data validation.

TypeUse it for
SMALLINT, INTEGER, BIGINTWhole numbers of growing size
NUMERIC(p,s)Exact decimals such as money
TEXTStrings of any length (use VARCHAR(n) only when the limit is a business rule)
BOOLEANtrue or false
DATE, TIMESTAMPTZCalendar dates and exact moments in time
UUIDGlobally unique identifiers
JSONBSemi structured documents that can be indexed
type[], ENUMLists, and small fixed sets of labels
Tip

Prefer TIMESTAMPTZ over TIMESTAMP, NUMERIC over FLOAT for money, and IDENTITY over the older SERIAL.

Module 06 · Beginner

CRUD: Create, Read, Update, Delete

The four everyday operations map to INSERT, SELECT, UPDATE and DELETE. RETURNING gives back the affected rows without a second query, and ON CONFLICT turns an insert into an upsert.

Caution

UPDATE or DELETE without WHERE changes every row. Run the same condition as a SELECT first, or wrap the change in BEGIN so you can ROLLBACK.

Querying: Filters, Joins, Aggregates

SQL is written in one order but evaluated in another. Knowing the real order explains most beginner errors, such as why a column alias cannot be used in WHERE.

FROM, JOIN then WHERE then GROUP BY then HAVING then SELECT then ORDER BY then LIMIT.

Join types

  • INNER JOIN: only rows that match on both sides.
  • LEFT JOIN: every left row, with NULL where nothing matches.
  • FULL JOIN: everything from both sides.
PracticeList every course that has no enrolled student.
Tip

List the columns you need instead of SELECT *. It is faster, clearer and does not break when the table changes.

PostgreSQL ships with hundreds of built in functions. Four families cover most daily work: text, numbers, dates and NULL handling.

Module 09 · Intermediate

Constraints, Relationships, Normalization

Constraints let the database defend its own data: PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL and CHECK. Application code has bugs; constraints do not forget.

  • One to many: a foreign key on the many side.
  • Many to many: a junction table with a composite key, as below.
  • One to one: a foreign key that is also UNIQUE.

Normalization in three lines

  • 1NF: one value per cell, no repeating groups.
  • 2NF: every column depends on the whole key.
  • 3NF: no column depends on another non key column.
Key takeaway

Normalize first for correctness, then denormalize deliberately where measurements prove a read is too slow.

Module 10 · Intermediate

Changing Structure: ALTER, Schemas, Sequences

Real projects change. ALTER TABLE adds, renames or removes columns without recreating the table. A schema is a folder inside a database that groups tables. A sequence is a counter that hands out numbers (identity columns use one internally).

Caution

DROP COLUMN and DROP TABLE delete data for good. On big tables, add new columns as nullable, backfill in batches, then add the constraint (see the production module).

11
Module 11 · Intermediate

Subqueries, Set Operations, CASE

A subquery is a query inside a query: scalar (one value), IN (a list) or EXISTS (is there a match). EXISTS stops at the first hit, so on large data it often beats IN.

  • UNION: combine and remove duplicates. UNION ALL: combine and keep duplicates (faster).
  • INTERSECT: rows present in both. EXCEPT: rows in the first only.
Key takeaway

Use UNION ALL whenever duplicates cannot occur or do not matter. Plain UNION pays for a sort or hash.

12
Module 12 · Intermediate

Indexes and Query Plans

Without an index PostgreSQL reads the whole table (Seq Scan). A B-tree index, the default, finds rows in logarithmic time and also serves sorting and range filters.

IndexBest for
B-treeEquality, ranges, ORDER BY (default)
GINJSONB, arrays, full text search
GiSTGeometry, ranges, nearest neighbour
BRINHuge append only tables ordered by time
HashEquality only (rarely better than B-tree)

Read the plan from the innermost line outward. Compare Seq Scan and Index Scan, the estimated and actual row counts, and the actual time. A big gap between estimate and actual usually means stale statistics: run ANALYZE.

Caution

Every index speeds reads but slows writes and uses disk. Drop duplicate and unused indexes.

Module 14 · Intermediate

Transactions, MVCC and Locking

A transaction groups statements so they succeed or fail together (ACID: atomicity, consistency, isolation, durability). PostgreSQL uses MVCC: each transaction sees a consistent snapshot, so readers never block writers.

Isolation levelBehaviour
READ COMMITTED (default)Each statement sees data committed before it started
REPEATABLE READThe whole transaction sees one snapshot
SERIALIZABLEBehaves as if transactions ran one after another; retry on failure
Tip

Keep transactions short. Long ones hold locks, block cleanup and bloat tables. Always take locks in a consistent order to avoid deadlocks.

15
Module 15 · Advanced

Advanced SQL: CTEs, Windows, JSONB, Views

CTEs (WITH) name an intermediate result and keep complex queries readable. Window functions compute across related rows without collapsing them like GROUP BY does: rank(), row_number(), lag(), running sums.

JSONB

Store flexible attributes next to relational columns, and index them with GIN.

Views

A view saves a query. A materialized view saves its result, trading freshness for speed.

16
Module 16 · Advanced

Recursive Queries and Hierarchies

A recursive CTE repeats a query on its own output. It suits trees and graphs: org charts, category menus, folders, bills of materials. It joins two parts with UNION ALL: the anchor (starting rows) and the recursive step (finds the next level). It stops when the step returns no new rows.

Caution

Cyclic data (A reports to B, B reports to A) loops forever. Keep a depth limit like WHERE c.depth < 20, or track visited ids in an array.

17
Module 17 · Advanced

PL/pgSQL Programming

PL/pgSQL adds variables, IF, loops and error handling to SQL. Use functions when a query needs a returned value, procedures (called with CALL) to run steps, and DO blocks for one off scripts.

  • DECLARE variables and SELECT ... INTO to fill them.
  • IF, ELSIF, FOR ... LOOP for control flow.
  • EXCEPTION WHEN ... THEN to handle errors, RAISE to report them.
Key takeaway

Prefer set based SQL over row by row loops. One UPDATE usually beats a loop of updates. Use PL/pgSQL for logic that plain SQL cannot express.

18
Module 18 · Advanced

Functions, Triggers, Partitioning

PL/pgSQL lets you run logic inside the database. A trigger calls a function automatically on INSERT, UPDATE or DELETE, which suits audit columns and small invariants.

Partitioning

Split an ever growing table by range, list or hash. Queries that filter on the partition key touch only the relevant partitions, and old data can be detached or dropped instantly.

Key takeaway

Do not load a whole large table into memory. Paginate with a keyset, stream with cursors and write in batches of a few hundred to a thousand rows.

19
Module 19 · Advanced

Replication, Extensions, Tuning

Physical (streaming) replication copies the WAL of the whole cluster for hot standbys and failover. Logical replication sends changes of chosen tables, which helps with major version upgrades and data distribution.

Extensions

Extensions add features without forking the database: pg_trgm (fuzzy search), pgcrypto, PostGIS (geography), pg_stat_statements (query statistics), TimescaleDB (time series).

First tuning knobs

  • shared_buffers: a common starting point is about 25% of RAM.
  • effective_cache_size: tells the planner how much the OS can cache, often 50 to 75% of RAM.
  • work_mem: per sort or hash step, so raise it carefully.
  • maintenance_work_mem: speeds up VACUUM and index builds.
  • max_connections: keep it low and use a pool.
Caution

Measure under the same load before and after every setting change. Tuning by guesswork often makes things worse.

20
Module 20 · Advanced

Security, Backup and Production

Use roles with the least privilege each application needs. Never let an app connect as a superuser.

Backup and recovery

pg_dump gives logical backups. For point in time recovery combine a base backup with archived WAL. Streaming replication keeps a hot standby, which can also serve read only traffic.

Running it for real

  • Put PgBouncer or another pool in front of the server.
  • Leave autovacuum on, and watch table bloat.
  • Track slow queries with pg_stat_statements.
  • Migrate big tables without long locks.
Caution

Destructive commands such as DROP and pg_restore --clean cannot be undone. Restore into a copy, verify, then switch.

21
Module 21 · Advanced

Row Level Security

GRANT controls which tables a role can touch. Row level security (RLS) controls which rows, enforced by the database itself. It is the standard tool for multi tenant apps where every customer must see only their own rows. A policy is the rule: USING filters rows that can be read, updated or deleted, and WITH CHECK validates rows being written.

Caution

Superusers and roles with BYPASSRLS ignore policies, and table owners do too unless FORCE ROW LEVEL SECURITY is on. Always test with an ordinary role.
